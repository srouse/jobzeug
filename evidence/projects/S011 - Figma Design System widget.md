## Account summary

Scott built a **Figma Design System** Community **widget** (personal) that tries to integrate design-system concerns (ADA, color/typography sets) with Figma structures (styles, components) and to explore how much of a design-system build tool can live **inside Figma**, using existing services (Font Awesome, Google Fonts, GitHub repos / npm packaging).

Public product framing (from figmadesignsystem.app / Community description): drag the widget on stage, name a system, build token sets, then **tokenize**, **transform** (CSS, SCSS, JavaScript, TypeScript), and **deploy** into a **GitHub-hosted npm package**. Site copy positions it for **small-to-medium** projects or first full design-system exploration — **not** large production design systems “quite yet.”

Capability spine from the published site (feature inventory, not a claim that Scott restated each bullet in this capture):

- **Color set tokens** — stepped color sets from a base/center color; sync to native Figma styles; multi-step editing; hue lock; ADA compliance feedback on steps.
- **Typography set tokens** — set patterns from base font/weight/size; Google Fonts previews/embeds; alert when fonts cannot be transformed to simple CSS.
- **Icon tokens** — SVG upload, stage selection, or Font Awesome; auto icon component with variants; spacing/offset per icon; paid Font Awesome kit + API token path.
- **Effect, breakpoint, custom tokens** — documented on the site (detail light in this scrape).
- **Component tokens** — site says **not presently implemented**.
- **Download / transform** — W3C tokens, CSS variables, Google font CSS embeds, JavaScript object; TypeScript/Atomic paths via GitHub deploy per site.
- **GitHub deploy** — create/configure a **new** repo and publish npm package; needs GitHub token with workflow and `read:packages` permissions (per site).
- **Style guide / lifecycle** — living documentation composition called out on the site.
